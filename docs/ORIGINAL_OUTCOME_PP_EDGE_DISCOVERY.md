# Exact modified-ROM original outcome/PP instruction edge recorder (source-only)

Checkpoint research batch, November 12, 2026. Adds a **read-only guest CPU observer** and strict offline verifier. DOES NOT install a hybrid hook or alter Current, original save, public main, opponent/NPC AI, or the separate exact modified target ROM. No active input injection, battle-item use or capture.

**Why:** The third independently encountered natural wild fixture already proved original actor0's two own PP writer debits and exact callback writes at original Thumb PCs `0x0808E33C` and `0x081AED58`, while battle flags remained stale. But the native battle **outcome decision PC is unproved**, and two earlier accepted native move submissions still have no matching native PP writer evidence. A callback transition is not a victory; a submitted move is not necessarily a PP-consuming attack.

**New `tools/trace_exact_outcome_pp_edges.c`** observes original CPU instructions before/after each guest step using the established private mGBA host ABI without any emulator memory writes or button presses. It records: (1) optionally supplied **unverified candidate** outcome byte writes (candidate=0 disables this watch, no guessed RAM addresses!), (2) original Main inBattle byte changes, (3) callback1/callback2 pointers, (4) Main phase, (5) original battle flags/pending changes, (6) all four original actor0 PP bytes, including exact writer vs confounding copy PCs, and (7) original player emitter, reply and manual move-menu PC markers. Each event carries the original executed Thumb PC, CPU pre-instruction registers, guest step/frame, native battle state and callback pointers. Event buffer and instruction/frame budgets are bounded; overflow returns failure status 3, incomplete step budget status 2, invalid input status 4. Only finished bounded status 1 may be analyzed by the verifier.

**New `tools/verify_exact_outcome_pp_edges.py`** verifies exact private Current+modified ROM+save hashes and all three original callback/PP writer 64-byte code windows, rejects malformed/synthetic edge ordering, unowned actor0 emit/replies, invalid addresses, malformed callback-store CPU register provenance, non-original PP source addresses, buffer overflows, active host move-menu input or guest RAM writes. The source checker has synthetic mutation coverage; its artificial fixtures are NEVER used as gameplay evidence.

**How to run an authentic trace later:** Privately load the existing exact modified ROM `4b2585e1...d3ee44`, protected original `.sav` copy, pinned mGBA host and an independently reconstructed naturally encountered second fixture. Use the C observer inside the existing private no-input stepping host. Begin with `candidate_outcome_byte_addr=0` so it discovers only original known fields/PP/actor0 marker lifetime. Only supply a nonzero candidate address after **separate original instruction/pointer evidence** identifies the candidate RAM byte; never infer it from upstream source offsets. Record the trace privately with schema `sg-original-outcome-pp-instruction-edges-v1`, exact SHA metadata, guest_writes=0, host_move_menu_inputs=0, new_hook_installed=false, status=1 and steps. `verify_exact_outcome_pp_edges.py --private-trace <private.json> --current <protected.gba> --modified <exact-modified.gba> --save <copy.sav>` verifies provenance. No private raw ROM, save, core state, host, or guest CPU trace should be committed to public GitHub/Drive. Public outputs can state counts and trace digest only.
