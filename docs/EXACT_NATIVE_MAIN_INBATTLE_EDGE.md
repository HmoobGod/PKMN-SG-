# Exact modified-ROM native Main.inBattle bit-1 transition observer (source-only)

2026-11-12. This is a diagnostic tool and an offline fail-closed test suite, **not** a playable change, native promotion, new outcome PC discovery, or certification of a finished battle. It does not touch Current ROM, original save, main, actor/foe controllers or NPC-partner AI.

## Why the targeted observer matters

The older unfiltered Thumb byte-store scout records changing small-value STRB stores across all EWRAM/IWRAM, and may fill its finite event buffer before the actual result/terminal phase. Its omission of a PC does not prove that PC did not execute. The already authenticated third natural wild fixture instead establishes `gMain` at RAM `0x030055D4`, and its `inBattle` flag is bit1 of byte `+0x439`, absolute `0x03005A0D`. At original callback handoff frame3984 onward, the flag was cleared while stale `gBattleTypeFlags=4`, `gBattlersCount=2` and pending=0 remained. Callback1 and callback2 original writers at 0x0808E33C and 0x081AED58 were independently witnessed. **The prior exact instruction that cleared inBattle has not been identified.**

`tools/trace_exact_main_battle_edge.c` adds a CPU-step read-only watch for any bit1 transition at `0x03005A0D`. For every transition, it records the guest instruction PC **before** `step(core)`, ROM Thumb halfword when the source PC is a supported ROM-address encoding, original pre-instruction registers, Main callback1/2 before and after, battle flags, pending, battler count, guest frame and step. This catches possible word writes and read-modify-write changes to the field that the previous STRB-only scout could miss; it does not assume the instruction is STRB or presume the surrounding result. The observer never modifies the game, save, guest state or user input.

A CPU-step-associated mutation is **not automatically the original store instruction** (especially for asynchronous/DMA effects) and an `inBattle` clear is **not equivalent to victory**. The original decision needs a separately authenticated battle-outcome variable, its original write and branch PCs, and original result interpretation. The observer supports bit1 edge detection; changing low-order bit0 alone is deliberately ignored because this field can toggle that bit in normal native engine activity.

## Outputs and evidence barriers

`tools/verify_exact_main_battle_edge.py` requires exact complete private ROM/save bytes at runtime, SHA checking, a bounded full-frame read-only original CPU transcript, legal wild/terminal context, monotonic steps, true bit1 transition sequence, and instruction bytes matching the exact modified ROM at each claimed original ROM PC. No event can certify win/loss, outcome writer, full unattended terminal, dynamic legality, request ownership, manual fallback, Android/save compatibility or production promotion. Results are **candidate-only** and remain private until independently reviewed. Public GitHub contains only source, tests, this documentation and identity hashes, not game ROMs, saves, original host, savestates or private raw CPU transcripts.

Mock test suite: `tools/test_exact_main_battle_edge.c` exercises a deterministic fake mGBA ABI, clear/set/low-bit events, capture limits, invalid inputs and instruction PC unknown. `tools/test_exact_main_battle_edge.py` checks fail-closed transcript schema and chronology.
