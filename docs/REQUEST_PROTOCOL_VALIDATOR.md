# Request-epoch consistency verifier — 16266 source-only follow-up

This is an **offline, read-only observer report validator**. It does not modify the 16266 scorer, installed hooks, ROM, save, state, enemy/NPC AI, or manual confirmation. It is not a runtime action gate, legal-target certificate, player-ownership check or proof that an automatic adapter is safe.

The native observer in `tools/probe_choice_lifecycle.py` records actor-0 buffer-A copies, emitter calls, six-byte replies, non-link completions, native restriction outcomes, and (for accepted non-cancel requests) slot/move/target commits. Its epoch IDs are **host-side observation counters**, not native identifiers.

Run:

```
python3 tools/test_choice_protocol.py
python3 tools/validate_choice_lifecycle.py /private/path/to/confirm.json /private/path/to/cancel.json
```

No private fixture or ROM is needed for unit tests; the optional second command reads private reports **locally** and prints aggregate counts. Do not publish reports without checking their contents.

## Fail-closed assertions

- The seeded request is distinguished from later observed buffer-A move requests; new requests are generated by a **copy event** rather than a pending flag, pointer, opcode or hash change.
- At most one actor-0 observed request is active. An emitter may submit once only while the request has pending bit0 and opcode19. Its reply must be a six-byte subcommand10 response matching the emitted payload exactly, followed by one non-link completion with bit0 cleared and the expected dispatcher callback.
- A cancel payload0xFFFF has no native validation/commit. A non-cancel request has one observed original-native restriction result0 or1. A result0 is followed by slot, move and target commit in order; a rejection has none.
- The per-epoch ledger must match the ordered event stream. The final request remains open for human input. Malformed or incomplete reports fail instead of silently receiving an approval.
- Different requests **may have identical 44-byte SHA-256 hashes**. The verifier does not deduplicate them. No hash, cached restriction byte, pending bit or host epoch ID is accepted as engine permission.

The six locally run unittest methods cover valid accepted/rejected/cancelled sequences, repeated-hash recovery, report nonmutation and 23 named protocol mutation cases, plus explicitly injected invalid commits after cancellation/rejection. These are synthetic checks, not emulator replay.

## Important evidence limits

The existing observer filters to actor0 at native breakpoints but omits raw register/actor provenance from its exported ledger. This verifier checks **internal chronology and ledger agreement**, not independent observer correctness, game-side epoch identity, encounter ownership, stale-freshness over interrupted callbacks, targets, effective choice-item/trait lock, hardware, phone, or emulator semantics. A forged internally consistent JSON could pass; that is not authorization.

There are no new gameplay acceptance passes. Native automatic Smart AI acceptance remains **0/20**. The next implementation milestone requires an engine-bound, player-only, exactly-once request authority and complete legality/target handling, with original native rejection recovery preserved.

Source-only CI runs the synthetic tests; private evidence and ROM are deliberately absent.
