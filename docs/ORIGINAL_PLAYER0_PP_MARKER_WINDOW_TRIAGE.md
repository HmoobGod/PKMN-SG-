# Original actor0 PP unmatched submissions: strict marker window triage

## Why a missing PP event is not automatically a cancellation
Earlier public outcome/PP tools can identify a Thumb STRB writer-PC
candidate when PRE-step CPU source/target and POST-step one-byte debit
agree. That still cannot tell whether the pending action was cancelled,
a native restriction was applied, PP belongs to a previous move, or
the original trace failed to include the relevant event.

This isolated helper runs the existing strict v3 verifier first, then
places syntactic PP writer candidates into bounded source-only
hypothesis windows beginning at each original player0 emitter marker.
A next emitter starts a new window. Any PP change before the first
emitter stays unattributed. Zero writer candidates is explicitly
UNCLASSIFIED, >1 is AMBIGUOUS, and exactly one is only UNVERIFIED.
Reply and completion marker counts are reported separately, never
conflated with unique engine-owned one-use request epochs.

Unrecognized Thumb instructions and >1 PP decrement fail attribution.
The public synthetic tests exercise absent, repeated, prior/next-window
and wrong-instruction PP writes, original event chronology, impossible
CPU fields and attempts to smuggle production privileges. No old
historical unmatched PP cause is classified, no false 'cancelled'
claim is generated. No original CPU sample is performed.

Source-only CI, independent exact-head Claude review and ancestral
PR79 approval required. No owner Current ROM/save/savestate/private
emulator, modified game or original CPU record read/staged/executed;
no item/capture, enemy/NPC AI, protected branch or manual fallback
modified. DRAFT/unmerged. Native 0/20, production 0%, PP causes 0/2.
