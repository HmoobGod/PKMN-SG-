# Source-only PR26 debugger capability negotiation proposal

LAB HOLD: this draft does NOT invoke a commercial game ROM, battery save,
savestate, live private GDB session or staged debugger. The independently
reviewed PR26 exact head remains unchanged, as do PR36–PR40 and main.

## Evidence behind this change

The upstream mgba-emu/mgba `0.10.5` source file
[`src/debugger/gdb-stub.c`](https://github.com/mgba-emu/mgba/blob/0.10.5/src/debugger/gdb-stub.c)
sets both breakpoint feature flags from `qSupported:swbreak+;hwbreak+`.
Without both flags, its breakpoint callback may emit nonstandard `S05k`.
The exact feature reply bytes are a constant independent of whether the
requested flags were actually set; this reply alone does NOT prove the
negotiation worked. In a separate, reviewed public generated-ROM experiment
(PR39) Ubuntu's real mGBA 0.10.5 returned exactly `T05hwbreak:;` at
synthetic PC 0x08000100 after negotiating the flags. The official build
and commercial game ROM were never tested in this procedure.

## Narrow source proposal (no automatic activation)

Add to PR26's RSP class only a manually invoked method that is eligible
on a new, stopped, untouched RSP connection. It sends the single exact
literal qSupported request and requires the complete source-observed reply.
Any malformed answer, framing failure or lost ACK permanently disables
further RSP commands on that instance; no retry or breakpoint manipulation.
Direct RSP.send(qSupported) is still rejected, as are other q commands,
arbitrary debugger writes, capture, unexpected memory ranges and external
connections. The default run_capture code does NOT invoke the opt-in method,
so it preserves the prior fail-closed behavior.

Add an entirely separate strict-public-stop guard: accepts only literal
`T05hwbreak:;`, still rejects S05k. This does not modify the
existing approved parse_stop grammar, interrupts, timeouts, PP logic,
ownership, game data, execution flow or production Smart AI.

All tests use only a fake GDB stub and generated bytes. There is NO live
probe or authorization to run any original/current user ROM or save.

Formal native acceptance 0/20 (0%), production 0%, unmatched PP 0/2.
Protected Current ROM/save, manual fallback, player-only restrictions, no
auto items/capture, enemy/NPC-partner AI and uncertified doubles unchanged.

Before any future actual private game use, require separate source/security
review, owner-specific explicit authorization for an isolated disposable
private-copy plan, exact modified-ROM provenance, original save protection,
and an independent gameplay acceptance checklist.
